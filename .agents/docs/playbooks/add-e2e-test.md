# Playbook: add an end-to-end test

Adding or extending a Playwright spec in `testing/`. Conventions and the reasoning behind them live
in `testing/AGENTS.md` — read it first; this file is the order of operations.

**Prerequisites, once per machine.** `.env` must exist at the repo root (`pnpm generate:env`):
`testing/src/support/env.ts` reads `API_DEV_SERVER_PORT`, `GATEWAY_DEV_SERVER_PORT` and
`WEB_DEV_SERVER_PORT`, and throws while `playwright.config.ts` is still loading if one is missing.
Browsers must be installed:
`pnpm --filter @opendatacapture/testing exec playwright install chromium firefox`. Nothing else
needs starting — `playwright.config.ts` launches api, gateway and web itself through each app's
`pnpm dev:test`, and the API brings up an in-memory Mongo replica set.

## Steps

1. **Add the `data-testid` in `apps/web`.** Selectors belong to the component, not the test —
   `apps/web/src/components/PageHeader/PageHeader.tsx` carries `data-testid="page-header"`. Use
   roles or labels only where no testid exists and adding one is not sensible.

2. **If the route is new, regenerate the route union:**
   `pnpm --filter @opendatacapture/testing gen:routes`. It parses `FileRouteTypes['to']` out of
   `apps/web/src/route-tree.ts` into `testing/src/generated/route.d.ts` (git-ignored, never
   hand-edited). Until it runs, the new literal is not a member of `RouteTo` and step 4 does not
   type-check. `apps/web/src/route-tree.ts` itself is regenerated by the user — never run that one.

3. **Write the page object** at `testing/src/pages/<mirror of the web route path>.page.ts`. Extend
   `AppPage` (`testing/src/pages/_app/route.page.ts`) for anything behind auth. For a public page
   extend `RootPage` (`testing/src/pages/__root.page.ts`) and set `readonly _requiresAuth = false` —
   the flag is abstract, and it decides whether `getPageModel` injects a token
   (`testing/src/pages/auth/login.page.ts` is the example). Read
   `testing/src/pages/_app/session/start-session.page.ts` for the shape.

4. **Register it in the `pageModels` map in `testing/src/support/fixtures.ts`**, keyed by the exact
   route literal — e.g. `'/datahub/$subjectId/table': SubjectDataTablePage`. The map is
   `satisfies { [K in RouteTo]?: any }`, so a key that is not a real route fails `tsc`. A page object
   missing from the map is unreachable from a spec.

5. **Write the spec** at `testing/src/specs/<flow>.spec.ts`, importing from the fixtures module:

   ```ts
   import { expect, test } from '../support/fixtures';
   ```

   Importing `test` from `@playwright/test` compiles and then silently has none of the fixtures
   below. `testing/src/global/setup.spec.ts` and `teardown.spec.ts` are the only files allowed the
   raw import.

6. **Navigate with `getPageModel('/route')`.** It authenticates as `actingRole`, navigates, and
   asserts the URL (`RootPage.goto` ends in `expect(page).toHaveURL(url)`). Routes with `$param`
   segments take a typed params object as the second argument.

7. **When the expected outcome is a redirect, `getPageModel` cannot be used** — its URL assertion is
   what the test is trying to disprove. Call `authenticateAs(role)` and then a raw `page.goto(...)`;
   see the standard-user cases in `testing/src/specs/authorization.spec.ts`. `authenticateAs` works
   through `page.addInitScript`, so it must run before the navigation it affects.

8. **Seed preconditions through the API, not the UI.** The worker-scoped `api` fixture is an
   admin-authenticated `ApiClient` (`testing/src/support/api-client.ts`) exposing `createGroup()` and
   `createUser()`. Drive the UI only for the behaviour under test.

9. **Name every record you create with the `uniqueId` fixture** — `` `Subject${uniqueId}` ``, never a
   fixed string. `fullyParallel` is on and all workers share one database, seeded once by
   `testing/src/global/setup.spec.ts` and dropped by `teardown.spec.ts`.

10. **Override the acting role per file or describe block** with `test.use({ actingRole: 'ADMIN' })`
    (default `GROUP_MANAGER`). `test.use({ appState: {...} })` controls first-run localStorage
    gating, which otherwise defaults to disclaimer accepted and walkthrough complete — see
    `testing/src/specs/disclaimer.spec.ts`.

11. **Add `@smoke` to the test title only for a critical flow.** The `firefox` project in
    `playwright.config.ts` greps `/@smoke/`; everything else runs on chromium alone.

## Verify

```sh
pnpm --filter @opendatacapture/testing lint                               # gen:routes, tsc, eslint .
pnpm --filter @opendatacapture/testing test:e2e src/specs/<flow>.spec.ts  # one spec; setup still runs
pnpm --filter @opendatacapture/testing test:dev                           # Playwright UI mode
pnpm test:e2e                                                             # whole suite, from repo root
```

Ignore the `test:chrome` script: its `--project='*Desktop Chrome'` matches none of the four project
names and errors immediately.
