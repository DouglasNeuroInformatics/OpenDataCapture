# docs

The Open Data Capture user manual, published as the Starlight section of opendatacapture.org. This
is **not** a workspace — there is no `package.json` and no test runner.

**This directory is the real content.** `apps/outreach/src/content/docs/en/docs` and
`.../fr/docs` are symlinks pointing here. Edit files at this path; a reviewer looking at the mirror
path sees the same bytes but nobody refers to them that way.

Read the root `AGENTS.md` first, and `apps/outreach/AGENTS.md` for how this gets built.

## Frontmatter

The collection is Starlight's `docsSchema()`, declared in `apps/outreach/src/content/config.ts` —
that file is authoritative. `title` is required; the rest is Starlight's standard set. Two local
conventions on top:

- **Every page carries an explicit `slug` that includes the locale**, e.g.
  `slug: en/docs/concepts/instruments`. All 34 pages do. Without it Starlight derives the URL from
  the file path, numeric prefixes and all. Follow the pattern `<locale>/docs/<section>/<name>`.
- Ordering within a section comes from `sidebar.order`. The `N.M-` filename prefixes are for humans
  reading the tree — they control neither ordering nor URLs.

`docs/en/4-concepts/4.1-instruments.mdx` is a good page to read before writing one.

## Adding a page

Dropping a file into an existing `docs/en/<N>-<section>/` is enough; the Starlight sidebar is
autogenerated per directory. **A new top-level section will not appear until you add an
`autogenerate` group for it** to the `sidebar` array in `apps/outreach/astro.config.ts`.

Use `.mdx` only when the page imports components. MDX here may import `@/components/…` and
`@astrojs/starlight/components`, which resolve through aliases declared in `astro.config.ts`;
**no other bare specifier will resolve** from a file in this directory, because these files live
outside the Astro package.

`apps/outreach/src/content/docs/en/runtime-core-docs/` is generated from runtime-core's TSDoc and is
not part of this directory. Do not hand-write API reference pages here.

## Language coverage

`docs/fr/` mirrors only `1-introduction`. An English page with no French counterpart is the normal
state, not a defect — do not translate the rest as a side effect of an unrelated change.

## Checking your work

No tests cover this directory. The build is the check:
`pnpm --filter @opendatacapture/outreach lint` (runs `astro check`) and
`pnpm --filter @opendatacapture/outreach build`. A broken `slug`, a missing `title` or an
unresolvable MDX import all surface there.
